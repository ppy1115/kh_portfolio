모듈 0 ▼

초기화

작업 공간을 깨끗하게 정리해서 새로운 작업 준비

동작 방식

  1. 불필요한 시트 삭제
  2. 기존 데이터 초기화

    ★인원별 집계 시트의 헤더는 유지하고 2행부터 전체 삭제

왜 이렇게 하나요? 이전 달 데이터가 남아있으면 새 데이터와 섞여서 에러가 발생합니다.

모듈 1 ▼

파일 불러오기

여러 개의 실적 파일에서 필요한 데이터만 정확히 가져오기

핵심 기능

  • 다중 파일 선택: 한 번에 여러 파일 처리
  • 파일명 자동 검증: To-Be 테이블과 비교하여 잘못된 파일 차단
  • 수식 처리: 지급금액이 수식인 경우(예: "=BD+BE") 자동 계산
  • 배열 사용: 10만 행 데이터도 3-5초 내 처리

성능 최적화

× 느린 방법 (행별 복사): 10,000번 반복
✓ 빠른 방법 (배열 사용): 한 번에 읽고 쓰기

속도 차이: 약 100배!

결과: 실적합체 시트에 모든 데이터 통합 완료

모듈 2 ▼

인원별 집계 준비

참고 시트에서 기본 정보(사번, 성명, 부서 등) 가져오기

KEY 시트 활용

"집계헤더" 테이블에 정의된 매핑 규칙대로 데이터를 가져옵니다.

매핑 예시:
헤더명: 사번  → 참고시트: 인원, 참고열: A
헤더명: 성명  → 참고시트: 인원, 참고열: B
헤더명: 부서  → 참고시트: 인원, 참고열: C

최종사업부 매핑

30개 팀 → 5개 본부로 그룹핑하여 보고서를 깔끔하게 만듭니다.

모듈 3 ▼

실적 데이터 매칭

실적합체의 금액을 인원별 집계에 정확히 매칭 (핵심!)

딕셔너리 활용 (성능 핵심!)

딕셔너리란? 전화번호부처럼 키로 빠르게 값을 찾는 자료구조

딕셔너리 구조:
키: "10001|복지포인트" → 값: 50,000
키: "10001|명절상여"   → 값: 100,000

검색 속도: O(1) - 즉시 찾음!

중복 처리

같은 사람이 같은 항목으로 2번 지급받으면 자동으로 합산합니다.

성능 비교

× 기존 방식: 500,000번 반복 → 약 5분
✓ 새 방식: 딕셔너리 + 배열 → 약 2-3초!
모듈 4 ▼

합계 검증

데이터가 정확히 입력되었는지 자동 검증

검증 로직

★인원별 집계 "복지포인트" 합계: 5,000,000
실적합체 "복지포인트" 합계:     5,000,000

검증: 5,000,000 - 5,000,000 = 0 ✓

만약 다르면:
5,000,000 - 4,900,000 = 100,000 ×
→ 에러 발생! 데이터 재확인 필요

결과: 데이터 정확도 100% 보장
